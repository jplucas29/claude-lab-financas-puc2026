# Checklist da entrega

## Vídeo de 2 minutos — roteiro sugerido

1. **O problema** (~20s): qual dor, de quem, por que importa. Uma frase forte.
2. **A solução funcionando** (~60s): mostre o artefato na tela, com um resultado concreto. Mostre, não conte.
3. **Como verificaram** (~20s): um exemplo de número que vocês conferiram na fonte.
4. **Impacto e próximos passos** (~20s): quem usaria isso e o que fariam com mais um dia.

Ensaiem uma vez antes de gravar. Uma gravação boa e simples vale mais que uma edição caprichada.

## Antes do deadline (15h30)

- [ ] **Vídeo** publicado (YouTube não listado ou Drive "qualquer pessoa com o link"), com até 2 min.
- [ ] **Artefato** publicado. Abram o link numa **aba anônima** para conferir que está público.
- [ ] **GitHub** do time **público**, com o README preenchido (equipe completa, problema, solução, dados, verificação, limitações).
- [ ] Os links do vídeo e do artefato estão **dentro do README** do GitHub.
- [ ] Os três links foram enviados no formulário de entrega.
- [ ] Fontes dos dados citadas e aviso de "não é recomendação de investimento", quando aplicável.

## Se o time for finalista (5 min + 2 min de perguntas)

- Comece pelo problema e pelo resultado, não pela tecnologia.
- Tenham um **plano B** se a demo ao vivo falhar: o próprio vídeo ou prints.
- Combinem quem fala o quê.
- Estejam prontos para responder: *"como vocês sabem que esse número está certo?"*
